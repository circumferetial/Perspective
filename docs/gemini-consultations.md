## 第一轮：路线图（B > A 子集 > C 思想 > D 延后）

### 核心结论
1. **优先级**：B（Z3 nlsat 作 ∃-QF 神谕 + 候选生成/验证处理 ∃∀/∀∃）立即做；
   A 只做 1D 子集（一元根隔离 + 二次 Virtual Substitution）；C 只吸收思想；
   D（Lean/mathlib 后端）长期延后。
2. **不能直接把 `∃m∀x` 丢给 Z3**（易 unknown）：自己生成候选 m\*，把
   `¬∃x ¬φ` 的无量词反例检查交给 Z3。神谕只做判定，不出证明步骤。
3. **多参数最值**：不要手写 CAD；走"消元降维（韦达/结式）→ 1D 边界/驻点 →
   Z3 全称闭合"。高考题降维后通常只剩 1 个核心参数。
4. **纯几何**：保留"规则优先，代数兜底"双轨；不要转投面积法（圆锥曲线隐式约束下
   面积法失效）。Horn 规则链的天然天花板：倒角链组合爆炸、缺辅助构造、非典型局部图谱。
   建议 DD+AR 伴侣（有向角方程 + 线段比线性方程组，高斯消元后回写 FactBase）。
5. **解释层**：Derivation 应升级为 Proof IR，区分 `SemanticStep`（规则/代入/求导）
   与 `OracleStep`（Z3 等黑箱）；Narrator 只翻译 SemanticStep，OracleStep 诚实描述。
6. **三阶段路线图**：
   - 一阶段（3~4 月）：Z3 nlsat 接入 + 1D 半代数可行域 + 最值引擎 +
     ProblemSpec 放行单层 ∃∀；基准 2023 新高考Ⅰ 22(2)、全国乙 20 等。
   - 二阶段（4~6 月）：纯几何知识图谱（全等/相似/共圆/圆幂/角平分线）+
     DD+AR 伴侣 + 代数兜底；基准 IMO Shortlist G1。
   - 三阶段（6 月+）：受控构造搜索（数值探测引导）、多参数/分段、Proof IR 导出。

## 第二轮：五条工程结论 + C# 抽象建议

### 结论 1：e-graph 选 D（不引引擎），偷两个思想
- 理由：e-graph 不擅长多元多项式理想约化；用局部重写模拟群作用属抽象错配；
  当前 11 Fact + 11 规则的体量，半朴素 Datalog + 成本闸足够；.NET 无生产级 egg/egglog。
- 偷：① FactBase 加轻量 Union-Find（等价类合并，参考 KM-SCR）；
  ② Guided Equality Saturation（POPL 2024）的"中间检查点"思想。
- **我方采纳**：方向采纳；**修正**：Union-Find 只用于"查询期 id 规范化"，
  不改写既有 Derivation 的前提 id；**共线不能用 UF**（共线是超图不是等价关系）。
  检查点思想：`Derivation` 已是 DAG，需在规则里显式拆中间表达式，不新增结构。

### 结论 2：跨模型"结论相似"用 Erlangen + 标准形，不追新理论
- 2023–2025 无直接可用的新理论；TongGeometry 处理的是离散点置换对称去重。
- 方案：**视角门控的定理搬运**——Projective 层所有非退化二次曲线同轨道；
  Affine 层三条轨道（椭圆/双曲/抛物）。证明链只用 ≤Projective 规则时，
  标准形上的证明骨架可用 M⁻¹ 搬回任意二次曲线。
- 缓存 key：标准形曲线 + 锚定元素归一化后的**有理不变量**（交比/离心率等）。
- 红线：链中一旦出现 Similarity/Isometry 规则（角度/垂直/长度/面积极值），
  仿射搬运失效；Erlangen 门控天然防止错误搬运。
- **我方采纳**：待实施（`Scene.Transform` + 证明记录搬运 + 标准形缓存）。

### 结论 3：无 LLM 的辅助构造 = HAGeo 思路 + 数值巧合过滤
- 只做已有元素的数值探测不足以"无中生有"；但无需 LLM。
- 可抄：极简构造算子集（中点、垂足、对称点、极点极线交点、过已知点切线、
  原点平移齐次化）；把 DiscoveryEngine 改造成**数值巧合度过滤器**
  （候选点在随机实例上同时满足多条额外关系的程度 → 优先级）。
- 针对高考解析几何的专用构造只有 3 类：原点平移齐次化、补全对称点、极线/准线垂足。
- **我方采纳**：方向同意；先做 3 类专用构造（成本低），通用构造搜索延后。

### 结论 4：多参数最值管线（不手写多维 CAD）
1. 入口有理化/对称降维：圆锥曲线有理参数化、对称基 (s=x₁+x₂, p=x₁x₂)、
   焦半径线性化（消双根号）。
2. 区域剖分：内部驻点（KKT + 结式降一元）、1D 边界（不等式取等 → 复用一维引擎）、
   0D 角点（非退化过滤 → 严格 `>` 结论）。
3. 候选取优 + Z3 `¬∃` 闭合（去根号正则化 + 符号守卫）。
- 提示：`√A + √B` 直接送 Z3 会变 4~5 变量、易超时；先参数化/几何消根号。
- **我方采纳**：作为下一阶段主线；先做 2023 新高考Ⅰ 22(2) 降维探针，再决定接口。

### 结论 5：只做一件事 → 多变量降维与边界剖分最值引擎
- 理由：打穿高考解析几何压轴；顺手治 Simplify/Z3 压力；零新依赖 + 可解释。
- 风险：竖直线/无穷远分支漏解（必须伴生 DegenerateBranch）；结式系数膨胀
  （成本闸 + 数值初筛）；纯几何目标②会暂缓。
- **我方决定**：同意目标；按"探针 → 最小实现"推进，不先设计大接口（Rule of Two）。

### C# 抽象建议（第二部分）
- `Interface`：后端替换（`ISymbolicSimplifier`/`IAlgebraicOracle`/`IExtremaSolver`/
  `ICanonicalizer`）——强类型契约 + 能力元数据 + 三态 + 取消 + 证明片段。
- `delegate`：算法内部微启发式（辅助点打分、复杂度度量、剪枝）——无状态、频繁变化。
- `event`：只做可观测性/诊断广播，**严禁驱动主推理控制流**。
- 两类抽象：A 后端替换（可淘汰旧实现）；B 策略组合（Portfolio，按可读性/成本排序，
  不能互相淘汰）。
- 四条稳定锚点：核心 IR（ExactScalar/Statement/FactBase/Derivation/Narrator）←
  策略编排层 / 代数后端契约 / 启发式插件 / 可观测层。
- 三条防过度抽象铁律：① 数学对象（名词）不做 interface，只有算子（动词）做；
  ② 第三方类型止步 Adapter；③ Rule of Two——第二个实现出现前不抽接口。
- **我方采纳**：全部同意。**调整**：Portfolio 现在不建（只有一条主路径）；
  `IExtremaSolver` 等第二个实现（KKT 多维）落地后再抽。
