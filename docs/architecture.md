# Perspective 架构纪律（单一出处）

本文件是项目**架构决策与纪律**的唯一记录点；代码注释只放指针，不重复正文。
推导细节留在代码注释里；本文件只记"为什么这么定"。

## 1. 表示层：矩阵管几何本体，坐标卡只管 I/O

- **射影平面上的几何对象一律用齐次坐标 + 矩阵表示**：点/线/二次曲线 = 齐次向量 / 3×3 矩阵。
  射影变换、极线、退化、交比都是矩阵运算，无需额外机制。
- **极坐标等非线性坐标卡只出现在输入/输出边界**（`PolarCoordinates`），
  转成齐次点后立刻丢弃角度。原因：二次曲线在 (r, θ) 下含根号与三角函数，不再是多项式；
  角度多值、原点处角度未定义，不适合进入推理内环。
- 标准位置构造函数（`Conic.Ellipse/Hyperbola/Parabola/Circle`）只给标准形；
  平移/旋转/伸缩一律用 `Conic.Transformed(Matrix3x3)` 组合，
  **不为每种变换组合写重载**（N 种变换是 N! 种重载，而一个矩阵入口覆盖全部可逆变换）。

## 2. 层级纪律：任何结论都要标"在哪个变换群下有意义"

- 变换分类：`PerspectiveTransform.Classify` → `TransformLevel`
  （Isometry < Similarity < Affine < Projective < Singular）。
- 曲线分类：`ConicTools.Classify` → `ConicClassification.MeaningfulAt`
  （椭圆/双曲/抛物 = Affine；圆 = Similarity；退化 = Projective）。
- 规则守卫：`TheoremEngine` 用 `facts.CurrentLevel > rule.RequiredLevel` 屏蔽越界定理。
- 原则：**坐标公式是某个坐标系下的表示，只有群不变量才是几何事实**。
  写新定理前先问"它在哪个群下不变"，再决定能否用坐标公式。

## 3. 严格性纪律：快通道负责筛，严通道负责结论

- 每个数同时带 double 近似（快）与 AngouriMath 精确表达式（严）。
- 纯近似数据（拖拽、数值拟合）**不得冒充严格结论**：
  `ConicClassification.IsExact = false`、`ProofStatus` 分级、`StrictResult` 四级。
- 证明类判定必须先走廉价的 O(1) 事实查询，再走昂贵的符号化简
  （代价递增排序；实测顺序错误会带来约 1000 倍耗时差）。

## 4. 定理规则契约

每条规则必须：
1. **前提清单**：在 XML 注释里写 前提/结论/推导/等级 四段；
2. **前提回验**：不信任 FactBase 里的标签，用严通道复核坐标级前提
   （如 `ConicTools.IsPolarLine`、`GeometryAudit.IsMidpoint`、`Conic.ContainsStrictly`）；
3. **结论落库前验证**：结论本身也要过严通道，失败即跳过（宁缺毋假报）；
4. **只增不改**：`FactBase` append-only，规则重复执行由 `AddFact` 去重保证幂等；
5. **声明 `ConclusionTypes` 与 `PremiseTypes`**：这是目标导向推演的元数据，
   必须如实反映规则输出与依赖的事实类型。

## 4b. 推演策略：BFS 与目标导向并存

- `RunToFixedPoint`：数据驱动 BFS，所有规则对所有事实跑到不动点。完备但会产生大量
  无关事实（实例场景实测：11 条规则全开推出 250 条事实）。
- `Prove(facts, targetFactType, ...)`：**类型级反向链**。从待证结论的事实类型出发，
  反向闭包出"可能产出该类型"的规则子集，只激活这些规则。同一场景实测：只需激活
  3/11 条规则、产生 21 条事实即可证出同一结论。
  反向闭包按类型取超集，**只会多激活、不会漏规则**，结论仍由规则内部严通道保证，
  因此是完备性的保守近似，不是启发式剪枝。
- 待证命题没有对应事实类型时（垂直/平行），跳过推演直接走代数预言机。
- 未采纳的备选：**反证通道**（把待证命题当假设注入，允许未验证前提参与推导，
  若某条规则的结论严格验证失败则判定矛盾）。它只能证伪、且依赖"假设→可检验后果"
  的规则链，链条断了就既不矛盾也证明不了，因此不适合作为主证明器。

## 4c. 解释层与计算层分离

- **计算结构不携带自然语言**：规则只记录 `Derivation(RuleId, Fact, Premises[])`，
  不拼字符串；`FactBase.DerivationLog` 是结构化证明记录。
- **解释文本集中在 `ProofNarrator`**：按 `RuleIds.*` 模板渲染。改文案、换语言、
  出 LaTeX 都只改这一个文件。
- `RuleIds` 常量表是规则与解释层的稳定键，避免两边各写魔法字符串而漂移。
- 写入 API 分离：初始条件/辅助连线用 `AddFact(fact, note)`；规则导出用
  `AddDerivedFact(fact, ruleId, params premises)`。**刻意不共用同一个名字**——
  零前提时 params 重载会与 note 重载产生歧义，导致规则记录被误当成初始条件。
- 迁移状态：11 条规则**全部迁移**（规则代码中不再出现自然语言）。

## 4d. 验证策略：回归测试防已知，属性测试防未知

- **回归测试**：把已发现的 bug 与已验证的结论固化（`Perspective.Tests`，54 例）。
  它只能防止"同样的问题再犯"，不能证明系统没有未知错误——这点必须诚实。
- **属性测试**：随机生成实例，断言**不变量**而不是记答案。已覆盖：
  射影变换保共线、射影变换保交比（随机整数 3×3 可逆矩阵）。
- **双通道**：符号严通道给结论；数值探针做快速排除与独立抽查。
  两者冲突时以符号通道为准，但需人工复核（可能揭示简化器的错误）。
- **反例必配**：每条规则/工具都要有"伪造标签反例"，防止前提回验被绕过。

## 4e. 数值与表达式卫生：齐次坐标归一化

- **问题**：齐次构造逐层乘尺度因子。交点/极线/中点复合几层后，虽然真实点是 (12/7,−2/7)，
  齐次坐标可达 1e11 量级；精确表达式树膨胀导致化简失败，double 近似也会溢出/抵消。
- **处理**：`HPoint.Normalized()`（有限点除以 W 使 W=1；无穷远点除以最大方向分量），
  在 `Conic.Intersect` / `Conic.OtherIntersection` 出口应用。`HLine.Intersect` 暂不归一
  （实测归一化会让数值预筛变准、从而暴露组合规则的真实成本，见下）。
- **严通道顺序**：**有理函数通道优先**（`AsSingleFraction` → 分子 ≡ 0），再退到
  `Simplify` / `Expand`。实测某真题的参数恒等式：99.5s → 0.55s（约 180×）。
  门控：只有表达式含除法节点才走有理通道，纯多项式直接化简。
- **组合型规则成本闸**：完全四点形规则是 O(C(n,4))，设 `MaxPool=6` 与单次产出上限 36。
  归一化修复了数值预筛的漏判后，同一场景会合法地发现更多事实——这是正确性提升，
  但必须用成本闸控制，否则一个演示场景要跑 50s。
- **教训**："数值不大"不等于"中间量不大"；数学代码的性能问题常常出在表示的尺度上，
  而不是输入规模上。

## 4f. 一次运行内的验证缓存（什么该存）

- **能缓存**：只依赖坐标的判定（`IsHarmonic`、`ContainsStrictly`、`Collinear`、`IsTangent`）。
  坐标在事实库里是只增不改的，重复调用结果不变。入口：`FactBase.CachedCheck(key, compute)`。
- **不能缓存**：依赖"事实是否存在"的判定（例如"找不到某条极线"）。事实库是 append-only，
  后续规则可能补上该事实；缓存失败会导致**漏推**。
- **候选池 = 结构化点**：组合型规则只枚举用户/题面声明的点（`FactBase.StructuralPointIds`）；
  规则生成的派生点默认不参与，需要时用 `PromoteToStructural` 显式提升。
- **截断必须可见**（防"砍候选点漏掉偏题"）：候选被池上限截断、或单次产出达到上限时，
  规则把提示写入 `FactBase.Diagnostics`，调用方可检查"是否可能漏解"，不再是静默丢弃。
- 实测：四点形候选池 6→5 后，BackwardChaining 测试 7.6s → 4.6s，全部测试 9s → 4s；
  代价是"可能漏解"，但已由 Diagnostics 显式报告。
- **每 pass 产出上限 + 缓存**：组合型规则设 `MaxFactsPerRun` 后会分多个 pass 继续，
  缓存让后续 pass 跳过已验组合（实测四点形规则 pass1 1.43s / pass2 2.59s，
  pass2 只算新组合，pass3 0s）。
- 缓存键用规则名 + 实体 id（坐标不随运行变化），缓存随 `FactBase` 生命周期自动失效。

## 4g. 外部代数神谕（Oracle）的定位

- **Core 只定义接口**：`IAlgebraicOracle` / `OracleVerdict`（无原生依赖）。
  可选项目 `Perspective.Oracle.Z3` 引用 `Microsoft.Z3`，Core 与主测试不受污染。
- **神谕只回答"可满足性"**：`DecideExists(变量, 约束)` → Unsat / Sat(模型) / Unknown。
  全称命题通过取反归结（`DecideUniversal` = 检查"反正例"是否可满足）。
- **不生成证明步骤**：结论记为一等节点 `OracleStep(claim, constraints, solver, verdict, model)`，
  解释层只允许诚实描述（"经实代数判定不存在反例"），**禁止解析/编造判定器内部推导**。
- **当前片段**：有理系数多项式（+−×、整数幂展开、除以有理常数）。
  根式/变量分母等非多项式节点返回 `Unknown`，待 M1-c 用"新变量 + 平方约束"正则化。
- **责任边界**：判定结果的确定性与完备性由外部判定器承担，本项目不背书；
  本项目只负责约束编码正确性与如实转述（Unknown 不得当作真/假使用）。
- **测试隔离**：`Perspective.Oracle.Z3.Tests` 独立成项目——Z3 原生库会显著拖慢
  测试进程启动，不能污染 `Perspective.Tests` 的快速回归。

## 4h. 外部构造注入（Proposer / Verifier 分工）

**动机**：用户或外部 LLM 可能想到一个"惊艳的辅助构造"，而我们的规则库没想到。
系统的职责不是猜出它，而是**严格验收**它。这正是 AlphaGeometry / HAGeo 的分工：
LLM/启发式负责"提构造"，符号引擎负责"验真假"。

**入口**：`ConstructionEngine.ProposePoint(facts, id, point, claims, proposedBy)`。

| 步骤 | 行为 |
|---|---|
| ① 声明 | 外部给出点坐标 + 应满足的关系（`ClaimPointOnLine` / `OnConic` / `Midpoint`） |
| ② 验证 | 逐条走严通道；任一不成立即**拒绝**，返回具体哪条失败 |
| ③ 登记 | 全部通过才写入：结构性点 + 对应事实，`Derivation.RuleId = external-construction`，`Note` 记录来源（user/llm/search） |
| ④ 使用 | 与机器构造地位相同，照常参与规则链与反向链 |

**设计要点**：
- 验收失败**不污染事实库**（不写任何事实），避免"错误构造"污染后续推理；
- 来源写进 `Derivation.Note`，解释层可如实叙述"该步由外部建议、经验证成立"；
- 未来的构造搜索只是另一个 Proposer，复用同一验收通道；
- 支持**点**构造（线上点/曲线上点/中点/垂足）与**直线**构造（过两点/平行/垂直/极线/切线）；\n  圆锥曲线本身的构造待扩展；平行/垂直暂只验收不登记事实（待 P1-4 补 ParallelFact/PerpendicularFact）。

## 4i. 集成优先：我们做胶水，不做重造

**原则**：强的东西（CAS 化简/消元、SMT/QE 判定、数值优化器、形式化内核）由成熟的库承担；
本项目负责把它们**粘合**成一条可验证、可叙述的推理链，而不是重写它们的弱版本。

| 角色 | 谁来做 | 我们负责什么 |
|---|---|---|
| 重计算（化简/消元/判定/优化） | 外部强库（AngouriMath、Z3、未来可接 SymPy/QE 后端） | 契约、能力声明、三态结果、超时与降级 |
| 结果可信 | 外部库给候选/判定 | 用严通道 + 神谕做**反例检查**，绝不盲信 |
| 可解释 | — | 每个外部步骤记成 `OracleStep`/`Derivation`，解释层只诚实转述 |
| 组合与编排 | 本项目 | 按问题形状分派后端；规则链优先，重计算兜底 |

**判定标准**：接一个强库 ≫ 手写它的弱版本；但任何外部结果必须能回到
"我们的三态 + 证明记录"，否则不允许进入结论（不可解释的"我算出来了"不接受）。

**已接**：AngouriMath（符号化简/求解）、Z3 nlsat（∃-QF 判定）、
SymPy（子进程 + JSON，`ISymbolicBackend`，零 native 构建）。
**候选**：SymPy（更强的化简/消元/因式分解）、QE 后端（CAD/VS 型）、
数值全局优化器（仅作候选生成，最终仍要严格反例检查）。

## 4j. 题板与题型模板（多问依赖）

- **陈设（ProblemScene）** = 共享 `FactBase` + 参数表 + 已答各问；它是"一道题的公共上下文"。
- **模板（IProblemTemplate）** = 输入陈设 + 槽位，输出 `ProblemAnswer`（值/解集/可达性/严格性/步骤链）；
  模板只做装配与格式化，数学仍由已有组件完成。
- **多问依赖**：`ProblemBoard.UseAnswerAsParameter` 把上一问数值结论注入参数表；
  已证事实留在共享事实库。这样"第 (2) 问用第 (1) 问结论"不需要特殊机制。
- **两类输入**：求解型 = 陈设 + 槽位（曲线 id、参数名、表达式）；
  证明型 = 陈设 + 结构化 `GeoClaim`。模板都不解析自然语言题干。

## 5. 事实模型

> 完整的事实/定理清单见 [facts-theorems.md](facts-theorems.md)（单一出处）。

- 事实用 `record` 以 ID 绑定，天然值等价去重；
- 唯一写入入口 `FactBase.AddFact`，同时维护按类型视图与按 id 索引；
- 规则用声明式查询表达前提（`LinesThrough`、`PointsOn`、`HasOnConic` 等），
  不手写全表扫描；
- **规则自动生成的辅助点必须加 `AUX:` 前缀**（如 Pascal 的交点、四点形的对角点）。
  这类点只用于让事实可引用，**不得参与"顶点/直线枚举"**——否则下一轮规则会把它
  当成新的结构性对象，导致组合爆炸与错误构造。同理，辅助点的 id 必须包含生成它的
  完整上下文（例如四点形的四个顶点），禁止只按一条边命名，否则不同构形会撞 id；
- **幂集事实**（`CollinearFact` 三点共线、`ConcurrentFact` 三线共点）无法按单个 id
  索引：去重靠**排序后的三元组规范键**（`Create` + `AddFact` 内规范化），检索靠
  **按对索引第三元**（`ThirdPointsCollinearWith`、`ThirdLinesConcurrentWith`）。
  新增同类事实时必须同时补"规范化 + 对索引"，否则会出现排列重复或检索退化；
- 待证命题（`GeoClaim`）**不入 Facts**，防止循环论证；
  `ProofJudge` 先跑定理链，未命中再用代数预言机，并标注 `TrueByAlgebraOnly`
  仅表示"该坐标实现为真"，不等于"从前提可推"。

## 6. 加新定理/新事实类型的检查清单

1. 结论能否用**已有事实类型**表达？能用就不加新类型（成本最低）。
2. 若必须加类型：先确认查询方式（幂集事实如 Collinear/Concurrent 无法按 id 索引，
   会放大扫描），再在 `AddFact` 里补索引与类型视图。
3. 规则的前提是否都能严通道回验？不能回验的前提要显式注明"trusted"。
4. 是否有退化情形（重合点、无穷远点、相切、除零）？在注释里写明处理方式。
5. 补一个正例 + 一个反例（伪造标签）验证，再提交。

## 4k. 等式后端契约（E）

**分工**：`IAlgebraicOracle` 判定"∃ 实解"（反例）；`IEquationalProver` 证明"generic 等式蕴含"。
两者方向不同，不得互相替代。

**状态映射（接线的 soundness 规则）**

| 后端结果 | 语义 | 处理 |
|---|---|---|
| `Proved` | 假设下目标 ≡ 0，无附加假设 | 可记 `StrictlyTrue`，来源标后端 |
| `ProvedUnderAssumptions` | 仅当列出的 NDG（多项式 ≠ 0）成立 | 条件证明；NDG 必须外显，不得静默当无条件真 |
| `Unknown` | 未证（可能假、可能能力不足） | **永远不得当作假** |
| `InconsistentHypotheses` | 假设集矛盾（空洞真） | 显式标记，不得静默当证明 |

其它红线：非等式片段（不等式、根式、分母含变量、超越）拒绝或转 Z3/证书层；
可约约束不做因式分解时只覆盖 generic 分支；迭代/规模超限返回 `Unknown`。

当前实现：
- `Perspective.Oracle.Z3.Z3EquationalProver`：参考后端（Z3 直接判定，用于验证契约与状态映射）；
- `Perspective.Constraint.WuEquationalProver`：吴特征列后端（从实验分支原样移植 `Monomial`/`PolyExpr`/方程管线，薄适配 `RelationStatement` 解析）；伪除初始式作为 NDG 通过 `ProvedUnderAssumptions` 外显。
两个后端对同一组等式系统做交叉校验：Wu 声称可证（含条件证明）时，Z3 必须也判 Proved。
