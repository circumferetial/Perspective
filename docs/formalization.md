# 命题形式化归约手册（Perspective）

本文件回答一个问题：**一道题从自然语言到可推形式，中间那一段怎么走？**
它是"记录只一处"的落点：目标模板、量词消去规则、能力边界都记在这里，代码注释只放指针。

## 1. 三层翻译

```
自然语言命题
   ├─ ① 场景登记：对象 → 坐标/矩阵 + 输入事实（FactBase）
   ├─ ② 命题形式化：语句 → Goal 模板（本文件第 2 节）
   └─ ③ 求解/证明：量词消去 + 严通道验证（本文件第 3 节）
```

①③ 已有实现；② 目前靠人工（或 AI 辅助）完成，**这就是与 Lean 形式化同性质的、无法完全自动化的一步**。
本手册的目标不是消灭这一步，而是让它**类型化、可报错、可叙述**。

## 2. 四个标准 Goal 模板

命名借用 FormalGeo 的 Goal 分类 + I2GATP 的 ndg 约定：

| 模板 | 字段 | 语义 | 现有实现 |
|---|---|---|---|
| `VerifyRelation(Predicate)` | 谓词 + 对象 id | 判定共线/共点/垂直/平行/相切/在曲线上等 | `ProofJudge` + `GeoClaim` |
| `SolveRange(Expr, Ineq, Var)` | 表达式 + 不等式方向 + 变元 | 求参数范围（如 Δ>0） | `InverseExamSolver.SolveSecantRange` |
| `FindLocus(Mover, Tracer, Domain)` | 主动点、追踪点、定义域约束 | 求轨迹方程（如中点 M(k) 的轨迹） | `DiscoveryEngine.DiscoverPointLocus` |
| `ExistsInvariant(ExistsVars, ForAllParams, Condition, NDG)` | 待求未知量 + 全称参数 + 条件 + 非退化条件 | **定点/定值模板**（如"存在 E 使 k_AE+k_BE 为定值"） | `SolveFixedPointsForSlopeSum` / `FindFixedDistanceCenter` |

**NDG 必须显式**：`ExcludedParamsNote`（例如"k = −2 时直线过 E，斜率无意义"）就是 ndg，
应作为 `ExistsInvariant` 的一等字段，而不是临时字符串。

## 3. 量词消去：三条归约

**核心原则：机器不量化无限集合，只量化有限个多项式的系数。**

### 3.1 ∀ 参数 → 一维恒等式（首选，对应"归约 A"）

对"动直线系 l(t) 恒过定点"：

1. 取两个合法参数值 t₁、t₂，求交点 p₀ = l(t₁) × l(t₂)（一次 3 维叉积，O(1)）；
2. 验证一维恒等式 `A(t)·x₀ + B(t)·y₀ + C(t)·w₀ ≡ 0`（走 `VerifyStrictZero`）。

优点：绕开"按 t 展开系数方程组"的麻烦；直线束 l₀ + t·l₁ 甚至可直接 p₀ = l₀ × l₁。
**注意**：对 sin/cos/√ 等非多项式系数，本归约只在符号引擎能化简时成立；三角恒等式可能返回
`NearZeroUnproven`，不得当成"已证"。

### 3.2 ∃ 未知量 → 多项式方程组 + 结式消元

"存在 E 使 f(E,k)/g(E,k) 为定值 λ" 等价于：`∃(E, λ): f(E,k) − λ·g(E,k) ≡ 0`。
把 E、λ 当未知量，按 k 的系数展开成多项式方程组，用 `MathS.Polynomials.Resultant` 消去一个变量，
再回代验证 + 严通道复核。**结式会产生增根，必须回代滤除**（已在 `SolveFixedPointsForSlopeSum` 实现）。

### 3.3 轨迹 → 插值拟合 + 代回验零（不用 Gröbner）

动点坐标可显式计算时：采 6~9 个精确点 → SVD/线性求解齐次方程组得候选圆锥曲线 →
把符号参数坐标代回，验证单变量恒等式。比多变元 Gröbner 消元便宜几个数量级。
**不适用**于：无法参数化的隐式轨迹、次数未知的复杂轨迹——那才需要真正的消元。

### 3.4 范围与不等式：用集合代数，不自己写

"机器像人一样理解范围" = 三件事：**表示**（区间并集）、**集合代数**（并/交/差）、
**精确成员判定**。这三件事不需要自己实现：AngouriMath 的 `Entity.Set` 提供
`Interval` / `FiniteSet` / `Union` / `Intersection` / `Complement` / `ElementInSet`，
`Perspective.Core.Math.RealSets` 只做薄封装，固定"全集 = ℝ"与"非退化参数要抠掉"两个约定。

| 人的动作 | 机器动作 |
|---|---|
| 多个约束同时成立 → 求交集 | `RealSets.Intersect(a, b)` |
| 分类讨论 → 多个范围求并 | `RealSets.Union(a, b)` |
| 排除斜率无定义/B 重合等参数 | `RealSets.SubtractPoints(range, k0, …)`（即 NDG） |
| 判断某个值是否在范围内 | `RealSets.Contains(range, value)`（三态：真/假/无法化简） |

不等式在三个不同位置，难度差三个数量级：

| 位置 | 形式 | 状态 |
|---|---|---|
| 作为目标（求参数范围） | 解一元多项式不等式 | ✅ 交给 `Entity.Solve` |
| 作为 ∀ 的定义域限制 | $\forall k\in D: F(k)=0$ | ✅ 多项式恒等式自动对任意子集成立；只需另验 $D$ 内交点存在 |
| 作为轨迹的弧段 | $\exists k\in D:\ (x,y)=(x(k),y(k))$ 的像 | ❌ 需要半代数投影（CAD） |

端点可以是无理代数数（如 $1\pm\sqrt2$），保持精确符号；成员判定若集合表达式无法化简为布尔，
返回 `NoSymbolicData`，**绝不猜**。

## 3.5 库优先政策（不自己写，也不轻易说"不支持"）

| 层级 | 用什么 | 状态 |
|---|---|---|
| Tier 1 | AngouriMath：一元不等式求解、集合代数、符号化简 | ✅ 已用（`RealSets`） |
| Tier 2 | **Z3（`Microsoft.Z3` NuGet，底层即 C API）**：非线性实算术判定（nlsat） | ✅ 已验证可用（见下），待接入为"代数判定神谕" |
| Tier 2b | SymPy（外部进程）：多变量不等式化简 | ⏳ 本机有 Python 3.14、未装 SymPy；Z3 覆盖后可暂不接 |
| Tier 3 | 实代数 QE（QEPCAD / RAGLib） | ❌ 不接；真需要时外部进程 |

**Z3 实测**（探针验证）：
- `x²−2x−1=0 ∧ x>1`（即 x=1+√2）下判 `x>2` → SATISFIABLE；
- `k²−4<0 ∧ k<0` 下判 `k=−1` → SAT、`k=1` → UNSAT；
- `0<1+√2` → SAT、`3<1+√2` → UNSAT。
结论：Z3 能精确判定代数数比较与不等式组可满足性，**弥补 AngouriMath 对嵌套根式
`ElementInSet` 化简不可靠的短板**。但 Z3 只给判定、不产出人类可读区间，因此定位是
**判定神谕**（当 `RealSets.Contains` 返回 `NoSymbolicData` 时兜底），不替代 `RealSets` 的表示。

接入方式（已实施 M1-a）：独立可选项目 `Perspective.Oracle.Z3`（Core 不引入原生依赖）+
`IAlgebraicOracle` 接口；当前支持有理系数多项式约束的 ∃-QF 判定，
根式/分母待正则化。**带量词的 NRA 不直接交给 Z3**（易 unknown），
而是"候选生成 + 取反检查"。

原则：**能库则库**；只有"现成库确实不支持且必须做"才标"不支持"，并且要在本文件登记原因。

## 3.6 参数族与量词：符号坐标 = "对所有参数成立"

- **表达方式**：`ExactScalar` 本身就带符号基因，坐标里放符号变量即参数族；
  多参数（k、t、u…）自由组合，无需新类型。
- **语义**：谓词检验走 `VerifyStrictZero`，证明的是**恒等式**，即"对定义域内所有参数成立"
  （∀）；分母/退化参数值构成 **NDG**，不在定义域内。
- **有理函数**：符号简化器不做通分。严通道为此增加"化为单分式 + 证分子 ≡ 0"通道
  （`AsSingleFraction()` → `Divf.Dividend`），并识别 `Providedf`
  （形如 "0 provided not 1+k²=0"，其 Predicate 即 NDG）。
  已用期中题第 2 问的参数版验证：中点 M(k) 恒在定圆上可严格证明。
- **注意**：探针式谓词（如 `HPoint.IsAtInfinity`）对符号量只代表一次采样，不能当结论；
  枚举型规则（Pascal、四点形）不应把参数实体当作普通顶点，需显式约定。
- **辅助点**：按自由度分三类——固定点（0，`Fixed`）／线上点（1，`OnLine`）／
  一般点（2，`Generic`）；曲线上点（1，`OnConic`，有理参数化）。
  "任取的一般点不在某线上"这类**否定性前提不可证明**，用
  `FactBase.AssumePointNotOnLine` / `AssumeNonZero` 登记为 NDG；
  若谓词恒为零（构形退化），假设被拒绝。
- **不支持**：对参数的存在量词（"存在某个 t 使…"）与量词交替——它们属于求解器/消元层，
  不属于规则层。

## 3.7 度量层：距离 / 点积 / 角度 / 面积

- 实现：`Geometry.Metric`——`DistanceSquared`/`Distance`、`Dot`/`Cross`、
  `TanAngle`/`TanAngleUnsigned`、`TriangleArea2`/`TriangleArea`；全部精确（含根号基因）。
- **视角纪律**：度量不是射影不变量，只在 `Similarity` 及更低视角有意义；
  规则/命题用到度量时必须先检查 `CurrentLevel ≤ Similarity`。
- **去根号的正确姿势**：含 `tan∠` 的方程直接解不动，应平方成
  `cross² − tan²·dot² = 0`（根号被平方消掉），解出后再**回验 tan**——
  平方会引入符号歧义与退化增根（例：2022 新高考Ⅰ21(2) 的 cc=3 就是"弦过 A"的增根）。
- 反解入口：`InverseExamSolver.SolveChordSlopeForZeroSlopeSum`（弦族斜率和条件）、
  `SolveAreaFromTangent`（已知 tan 求面积）。
- **平方根本质上是多值的**：√ 作为关系有两个值（±），只有取算术平方根（主值）才是单值函数；
  复数域上更是两个分支。因此：
  - 代码里 `ExactScalar.Sqrt` 取**主值**，用于构造点坐标等"函数语义"场合；
  - "平方去根号"是在**关系语义**下解方程（解集包含所有分支），所以平方后**必须回验**
    才能钉住分支/符号——2022 新高考Ⅰ21(2) 的 cc=3 就是平方引入的、属于"弦过 A"的增根；
  - 复数分支切换（如根号换支）不在支持范围内，遇到只能报 `NearZeroUnproven`。

## 3.8 问题陈述的量词结构（Statement / ProblemSpec）

**表达形式**：把题目写成前束范式 `Q₁x₁…Qₙxₙ. φ`——根是量词节点（∀/∃），
内部是逻辑连接（∧/∨/¬）与原子关系（=, ≠, <, >, ≤, ≥）。实现见
`Reasoning.Statement`（AST）与 `Reasoning.ProblemSpec`（按形状分派）。

**为什么这样设计**：一阶逻辑中任何公式都可化为前束范式，所以"以 ∀/∃ 开头、内部嵌套"
在**表达能力**上足够描述一阶陈述。但"能表达"不等于"能判定"：

| 形状 | 判定方式 | 现状 |
|---|---|---|
| 无量词（常量） | 常量比较 | ✅ |
| 纯 ∀* | 恒等式验证（`VerifyStrictZero`） | ✅ |
| 纯 ∃*（单变量、单原子关系） | 方程/不等式求根（复根过滤为实根） | ✅ |
| 量词交替（∀∃ / ∃∀） | 需要量词消去（QE） | ❌ 报 `Mixed` + 原因 |
| 量词出现在逻辑连接内部 | 需先化前束范式 | ❌ 报"需前束化" |
| 多变量 ∃ | 结式消元 / 多变量 QE | ❌ 目前只支持单变量 |
| 高阶量词（"存在一种构造/策略"） | 二阶逻辑 | ❌ 超出范围 |

**设计原则**：分派前先分类，**不支持就明确报告形状与原因**（三值 `TruthValue.Unknown`），
绝不静默猜测。几何命题仍走 `GeoClaim + ProofJudge`，`Statement` 是"题目陈述"层，
两者在 `ProblemSpec` 里分工：代数陈述直接判定，几何部分编译成事实库再走定理链。

## 3.9 逻辑分层与本项目的映射（重要澄清）

**先更正一个常见误说**："最值/优化题不是一阶陈述" —— 不对。最值可以严格写成一阶：
`∃m (∃x. f(x)=m) ∧ (∀x. f(x) ≥ m)`。它是 **Π₁/Σ₁ 混合**形状，不是"非一阶"；
我们做不了是因为缺 QE/优化能力，不是逻辑上表达不了。

**真正超出（RCF 语言的一阶逻辑）的情形**：

| 情形 | 为什么超出 |
|---|---|
| 量词作用于**函数/集合**（"对任意连续函数 f…"） | 二阶逻辑（函数量词） |
| "**存在尺规构造**/存在一种作法" | 可构造点集不是 RCF 可定义集（它可数稠密，非半代数） |
| "**对所有自然数 n**" | ℕ 在 ⟨ℝ,+,×,<⟩ 中不可定义（o-minimality） |
| "**可证/不可证**"、"证明这个定理" | 元语言（证明论），不是对象语言陈述 |
| "求作/求解"（任务式要求） | 非真值陈述；可以改写成公式，但答案格式与搜索是额外层 |

**量词形状的常见分层**（回答"逻辑上划分蛮多"）：

| 分层 | 内容 | 与本项目 |
|---|---|---|
| 前束范式 | `Q₁x₁…Qₙxₙ.φ`（φ 无量词） | `Statement` 的结构 |
| 算术层级 | Σ₀=QF，Σ₁=∃*QF，Π₁=∀*QF，Σ₂=∃*∀*QF，Π₂=∀*∃*QF… | ProblemSpec 支持 Σ₀/Σ₁/Π₁ |
| 量词交替 | ∀∃ vs ∃∀（Skolem 化只对 ∀∃ 引入 Skolem 函数） | 交替 = 需要 QE，当前不支持 |
| 保持性定理 | ∀-公式对子结构保持；∃-公式对扩张保持 | 解释"为什么定理规则都是 ∀" |
| Horn / 几何逻辑 | `∀x. (前提₁∧…∧前提ₙ → 结论)` | **我们的定理规则正是这种 ∀-蕴含（Horn 形）** |
| 有序/多类逻辑 | 按 Point/Line/Conic 分 sort 量化 | 我们的 `GeoClaim` 按对象类型分派 |
| 广义量词 | "无穷多个"、"几乎所有"、基数量词 | 在 RCF 上多数可化归一阶（o-minimality），一般结构则不行 |

**关键区分**：**可表达 ≠ 可判定 ≠ 我们已实现**。
RCF 由 Tarski–Seidenberg 有量词消去（可判定），但 QE 代价随量词交替急剧增长；
我们的实现只是 RCF 的一个**受限片段**（恒等式 + 单变量求根 + Horn 规则链）。

## 3.10 量词顺序、依赖性与真题归类

**顺序不是排版问题，而是"见证量的依赖结构"**：

| 形状 | 含义 | 见证量 |
|---|---|---|
| `∃x ∀y φ(x,y)` | 存在一个**统一**的 x，对一切 y 都成立 | x **不能**依赖 y |
| `∀y ∃x φ(x,y)` | 对每个 y 都有（可能不同的）x | x **可以**依赖 y（Skolem 函数 x=f(y)） |

经典例子：连续性 `∀ε∃δ` vs 一致连续性 `∃δ∀ε`——前者 δ 可以依赖 ε，后者不能。
这正是"能不能对前面的变量做操作"的精确表述：**∀∃ 中的见证量可以依赖前面的 ∀ 变量；
∃∀ 中的见证量必须与后面的 ∀ 变量无关**。Skolem 化就是把这个依赖显式写成函数。

**真题归类**（对照 `Statement`/`ProblemSpec` 的能力）：

| 真题 | 小问的陈述形状 | 是否在 Statement 片段内 |
|---|---|---|
| 2023 新高考Ⅰ 22(1) | ∀P (P∈W ⟺ 方程)，Π₁ | ✅ 已解 |
| 2023 新高考Ⅰ 22(2) | ∀矩形 (3 顶点在 W → 周长>3√3)，Π₁ | ✅ 形状内；判定需不等式/优化 → 当前 Unknown |
| 2022 新高考Ⅰ 21(1)(2) | ∀弦（条件 → 斜率/面积定值），Π₁ | ✅ 已解 |
| 2022 浙江 21(ⅰ)(ⅱ) | ∃m (∀…≤m ∧ ∃…=m)，**交替** | ❌ 片段外（需 QE/优化） |
| 2022 全国乙 20(1) | 代数方程求解（Σ₁） | ✅ 已解 |
| 2022 全国乙 20(2) | **∃P ∀t (P∈HN(t))**，∃∀ 交替 | ❌ 片段外；DiscoveryEngine 用"猜候选+∀验证"绕过（不完备但有效） |
| 2020 上海 20(1) | 单变量方程（Σ₁） | ✅ 已解 |
| 2020 上海 20(2) | ∀配置（\|PF\|=8 → 角度定值），Π₁ | ✅ 形状内；判定需三角/度量 → 当前 Unknown |
| 2020 上海 20(3) | 表达式：∀b（恒等），Π₁；范围：∃∀ 交替 | 表达式 ✅；范围 ❌ |

**为什么 Q20(2) 特别难**：它要求的定点是**统一**的（`∃P∀t`，P 不能随弦变化），
这恰恰是 ∃∀ 而非 ∀∃——所以既不在我们的 ∃ 片段，也不在 ∀ 片段，只能靠"候选生成 + ∀验证"。

- **一维极值骨架（M1-b）**：`Reasoning.ExtremumSolver` 用
  "候选生成（端点 + 驻点）→ 神谕闭合"求解 `∃m(∀t∈D. f(t)≥m ∧ ∃t∈D. f(t)=m)`：
  选最优候选 m* 后，令神谕检查 `∃t∈D. f(t) < m*`（对 min）或 `> m*`（对 max），
  UNSAT 即证明该值为全局界，SAT 则返回反例（提示候选漏解）。
  无神谕时如实标注"未闭合"。示例：2022 浙江 21(ⅰ) 距离² 最大值 144/11。

- **有理目标极值（M1-b2）**：`ExtremumSolver.FindExtremumOfRational` 处理 f=N/D（D>0）：
  驻点用 N'D−ND'=0（保持多项式），闭合用 `N − v·D` 的符号——**始终不把变量放进分母**。
  示例：2022 浙江 21(ⅱ) |CD|² 最小值 180（|CD|=6√5）。
- **二次型限制到直线**：`Conic.RestrictToLine` / `IntersectionChordLengthSquared`
  给出无根号弦长 |d|²(b²−4ac)/a²；对"线对"退化二次型（如 PA∪PB）同样适用，
  可把"两条线与定直线的落点距离"直接化成对称量。
  **反例教训**：显式算出 A、B 的根号坐标再求交点，表达式复杂度 3511 且化简失败；
  换线对矩阵后复杂度 19——**先消元、再计算**是硬约束。

## 3.11 题目现场的新等式/不等式：约束，不是"事实"

**场景**：题目直接给出一个库里没有的新等式/不等式（如 $k>0 \wedge k^2<2$、
"某四点满足某乘积关系"）。这类东西**不应该进事实库**——它是**问题实例的约束（hypotheses）**。

**正确表示**（已在代码里）：约束 = `Expression + RelationKind` 的**数据对象**
（`RelationStatement`），变量用符号坐标声明。它不是 `Predicate`/`Func`。

| 关注点 | 载体 | 说明 |
|---|---|---|
| 约束的**内容** | `ExactScalar` 表达式 + 关系符号 | 可代入、可消元、可求导、可交判定器 |
| 对象的**构造** | `HPoint`/`HLine`/`Conic` 等函数 | 函数只构造符号对象，不承担真假判定 |
| 真假**判定** | 严格通道 / 外部神谕 | 只判真假，不表达知识 |

**为什么不用 predicate/delegate**：delegate 只能对"具体数值"判真假，
无法参与代数运算（代入、消元、求导、交给 nlsat），也无法被解释层叙述。
一旦把新约束写成匿名函数，它就变成不可操作的黑箱。

**闭合方法**：`H₁ ∧ … ∧ Hₙ ⇒ C` 等价于"反正例" `∃vars (H ∧ ¬C)` 不可满足，
交给 `IAlgebraicOracle`（见 `ProblemSpec.CheckEntailment`）。
三值返回：Unsat ⇒ 成立；Sat ⇒ 反例（可定位漏条件）；Unknown ⇒ 如实上报。

**语法层**：`Statement.Implies(前提, 结论)` 支持把"证明题"写成量词树；
但纯符号引擎只能判恒等式，**假设下的蕴含需要判定器闭合**——测试里已显式区分
"语法可分类（Unknown）"与"判定器闭合（True）"。

**注意**：根号平方要带符号约束；严格不等式要写全非退化条件；
量词交替与变量规模要先做几何化简/降维，再交判定器。

## 4. 明确的能力边界（不做的部分）

| 类型 | 状态 | 原因 |
|---|---|---|
| 等式型关系（共线/共点/相切/在曲线上…） | ✅ | 已有事实类型 + 严通道 |
| 定点 / 定值（∃∀ 等式型） | ✅ | 结式消元 + 一维恒等 |
| 参数范围（简单不等式） | ⚠️ 有限 | 用 `Entity.Solve` 解一元不等式；一般不等式组/最值需要区间算术或 CAD，未做 |
| 轨迹的弧段/定义域约束 | ❌ | 需要半代数 QE / CAD（例：k<0 时中点轨迹只是一段弧） |
| 实分支/方向约束（如"交右支"、钝角判定） | ❌ | 复数域上的结式无法区分分支与方向 |
| 超越函数（sin/cos/指对） | ⚠️ 有限 | 需先做有理化代换；符号化简能力不足时只能报 `NearZeroUnproven` |
| 构造性存在（"作辅助线使…"） | ❌ | 属于综合法/构造搜索，不在代数归约范围内 |

**覆盖率的诚实估计**（早期调研笔记，待独立验证；仅供参考）：
高中解析几何的等式/轨迹/定点定值核心部分约 80%~90%；
若只允许系数匹配 + 简单结式、不做完整特征列/Gröbner，复杂竞赛平几约 30%~50%，深层嵌套会次数爆炸；
几何不等式与有向选枝类问题为 0%。

**已知限制：构造与定理选择的循环**。综合法的威力来自"一个好构造让结论变平凡"，但
好构造通常是从高层结论倒推出来的，而高层结论又要靠构造才看得见。人类靠经验类比打破
这个循环，机器只能靠穷举（组合爆炸）。因此本项目**不做自动构造搜索**；可行的替代是
"人给出构造提示（辅助点/线），机器负责验证与推演"，即把构造留给语义层、把推导留给严通道。
